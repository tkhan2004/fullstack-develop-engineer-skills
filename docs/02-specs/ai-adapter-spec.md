# Spec — AI Adapter Layer

Status: draft

Different agents consume instructions differently. The core MUST NOT know about any of them.

```text
Canonical Skills
      ↓
Skill Resolver   ←  Project Configuration + Project Profile
      ↓
Canonical Output  (tool-independent IR)
      ↓
AI Adapter ─┬─ Claude   → CLAUDE.md (+ .claude/skills/)
            ├─ Codex    → AGENTS.md
            ├─ Cursor   → .cursor/rules/*.mdc
            └─ Generic  → .engineering/generated/INSTRUCTIONS.md
```

## 1. Canonical output (IR)

```ts
interface CanonicalOutput {
  version: 1;
  project: {
    mode: "new" | "existing";
    strategy?: "adopt" | "recommend" | "migrate";
    architecture: { style: string; source: string; confidence?: number; strictness: Strictness };
    stack: StackSummary;
    constraints: string[]; // e.g. "Do not restructure the project."
  };
  sections: Section[]; // ordered, see skill-system.md §6
  references: Reference[]; // reference modules, key files
  lockfile: { skills: { id: string; version: string; selectedBy: string }[] };
}

interface Section {
  id: string; // skill id
  title: string;
  priority: number;
  body: string; // rendered markdown at the chosen strictness
  checklist?: string[];
  examples?: { bad: string; good: string; note: string }[];
}
```

Adapters consume **only** this. An adapter that reads `config.yaml` directly is a bug.

## 2. Adapter interface

```ts
interface AiAdapter {
  readonly id: string; // 'claude'
  readonly displayName: string;
  defaultOutputs(): OutputPath[]; // relative paths it owns
  render(output: CanonicalOutput, options: AdapterOptions): GeneratedFile[];
}

interface GeneratedFile {
  path: string;
  content: string;
  marker: "full" | "block"; // whole file vs. managed block in a user file
  blockId?: string; // for 'block'
}
```

## 3. Generated-file discipline

Full-file output starts with:

```md
<!-- GENERATED BY @engineering-skills/cli v0.3.0 — DO NOT EDIT
     Source: .engineering/config.yaml
     Regenerate: eng-skills generate
     Hash: sha256:7f3c… -->
```

Managed blocks inside a user-owned file:

```md
<!-- engineering-skills:start id=project-context -->

…generated…
<!-- engineering-skills:end id=project-context -->
```

Rules:

- Content **outside** a managed block MUST be preserved byte-for-byte.
- If the hash shows a generated file was hand-edited, `generate` MUST stop and ask
  (`--force` to overwrite, `--diff` to show).
- Adapters MUST NOT write outside their declared `defaultOutputs()` (or the configured
  override).

## 4. Adapters

### `claude`

- `CLAUDE.md` — project context + the condensed rule set, project facts first.
- Optionally `.claude/skills/<id>/SKILL.md` for large skill bodies, referenced from
  `CLAUDE.md`, when `ai.mode: reference`.

### `codex`

- `AGENTS.md`, single file, no external references (assume no file-following).

### `cursor`

- `.cursor/rules/*.mdc` with frontmatter globs so rules attach to the right paths.

### `generic`

- `.engineering/generated/INSTRUCTIONS.md` — plain, self-contained Markdown.

## 5. `reference` vs `inline`

| Mode        | Behaviour                    | Use when                                            |
| ----------- | ---------------------------- | --------------------------------------------------- |
| `inline`    | Everything in one file       | Agent cannot follow file references; small rule set |
| `reference` | Entry file + per-skill files | Large rule set; agent supports lazy loading         |

Default: `reference` for `claude`, `inline` for `codex` and `generic`.

## 6. Content ordering (all adapters)

```text
1. Project context      mode, architecture, strictness, hard constraints
2. Do-not list          the few absolute prohibitions (e.g. "do not restructure")
3. Reference modules    "imitate these files"
4. Core reasoning       onboarding → requirements → problem solving
5. Architecture         principles → selected style → dependency rules
6. Stack                language → runtime → framework → database
7. Quality              clean code → SOLID → review
8. Engineering          testing → security → error handling → …
```

The first 500 tokens carry the facts that make the agent behave correctly; everything after is
refinement.

## 7. Determinism

- Stable section ordering (priority, then id).
- No timestamps in content (version and hash only).
- LF line endings, trailing newline, no trailing whitespace.
- `generate --check` compares hashes and fails on drift.

## 8. Adding an adapter

1. Implement `AiAdapter` in `packages/adapters/<id>`.
2. Register in the adapter registry.
3. Add snapshot tests for a fixture config.
4. Document the output contract here.

No core change. If one is needed, the IR is incomplete — extend the IR, not the adapter's
reach.
