# P8 — Project Generation

**Entry** P6, P7 · **Exit** `generate && generate` → clean `git status`; `--check` fails on drift.

## `.engineering/` layout

- [ ] `config.yaml` — user-owned, hand-editable
- [ ] `project-profile.yaml` — generated by `analyze`
- [ ] `skills/` — project-specific generated skills (user-owned after first write)
- [ ] `generated/` — fully generated, safe to delete
- [ ] `generated/lockfile.yaml` — resolved skill ids + versions + reasons
- [ ] `generated/.gitignore` guidance documented (commit it — reviewers should see it)
- [ ] `migration-plan.yaml` when applicable

## `generate` command

- [ ] Loads config (+ profile if present), resolves, builds IR, runs adapters
- [ ] Write planner with create/update/skip classification
- [ ] `--check` — no writes, exit 1 on drift (CI guard)
- [ ] `--adapters` subset
- [ ] `--dry-run`
- [ ] Clear summary of what changed

## Project-conventions skill

- [ ] Generated from the profile: naming, file naming, test placement, error strategy,
      validation, reference modules
- [ ] Written to `.engineering/skills/project-conventions/SKILL.md`
- [ ] Marked as user-owned after first write; regeneration diffs and asks
- [ ] Included in resolution with high priority for `mode: existing`

## Lockfile

- [ ] Records skill ids, versions, `selectedBy`, config hash, CLI version
- [ ] Changed resolution without a config change → investigate (skill content drift)
- [ ] Used by `doctor` to detect stale generated output

## Tests

- [ ] Idempotence: generate twice → identical bytes
- [ ] `--check` fails after a manual edit to a generated file
- [ ] User content outside managed blocks preserved
- [ ] Deleting `generated/` and regenerating reproduces it exactly
- [ ] Existing project: no source file touched
